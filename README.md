## 🚀 How It Works

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  1. Submit   │───▶│  2. Agent    │───▶│  3. Bugs     │───▶│  4. PR with   │
│  Your Repo   │    │  Scans Code  │    │  Fixed       │    │  Fixes       │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
     You              8 PM IST           Auto                 You Review
```

### Step-by-Step

1. **Submit your repo** — Open an issue here with your repo URL using the template
2. **Agent scans at 8 PM IST** — Every night, the agent reviews your code for:
   - Python syntax errors & runtime bugs
   - Type mismatches and missing annotations
   - Logic errors and edge cases
   - Missing error handling
   - Security vulnerabilities (basic)
   - Broken imports and dependencies
   - Code quality issues (PEP 8, dead code)
3. **Fixes submitted as PRs** — Agent forks your repo, fixes bugs on a branch, and opens a PR
4. **You review & merge** — You get a clean PR with description, changes, and test notes

## 📋 How to Submit Your Repo

1. Go to the [Issues tab](https://github.com/as7111771-create/bug-fix-agent/issues/new/choose)
2. Select the **"Submit Repo for Bug Fixing"** template
3. Fill in:
   - Your repo URL (e.g., `https://github.com/username/my-project`)
   - Primary language (Python preferred)
   - What kind of bugs you want fixed
   - Any specific areas to focus on
4. Submit! The agent will pick it up at the next 8 PM IST run.

### Requirements

- Repo must be **public** (private repos require Pro plan)
- Python projects are prioritized
- Repo must have at least a `README.md`
- Must allow fork-based PRs
